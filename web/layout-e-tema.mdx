## A casca: `AppLayout`

`src/layout/AppLayout.tsx` é o componente que envolve **todas** as telas autenticadas. Ele monta os providers de layout e o esqueleto visual:

```text
AppLayout
└── SidebarProvider
    └── SearchProvider
        └── SupportChatProvider
            └── LayoutContent
                ├── AppSidebar + Backdrop
                ├── coluna principal
                │   ├── AppHeader
                │   └── <Outlet />          ← a tela da rota
                ├── SupportChatWidget
                └── AppBottomNav            ← só na área do cliente
```

| Arquivo | Responsabilidade |
| --- | --- |
| `src/layout/AppLayout.tsx` | Providers, esqueleto e a regra de cliente inativo |
| `src/layout/AppSidebar.tsx` | Menu lateral e navegação |
| `src/layout/AppHeader.tsx` | Cabeçalho: busca, tema, perfil |
| `src/layout/Backdrop.tsx` | Fundo escurecido quando a sidebar abre no mobile |
| `src/layout/SidebarWidget.tsx` | Bloco informativo no pé da sidebar |
| `src/layout/AppBottomNav.tsx` | Barra inferior do cliente no mobile (inclui a aba "Ajuda", que abre o chat de suporte) |
| `src/layout/clientNav.tsx` | Itens de menu do cliente e o link da central de ajuda (`VITE_HELP_CENTER_URL`) |

### Deslocamento da coluna principal

A margem esquerda do conteúdo reage ao estado da sidebar, lido de `useSidebar()`:

| Estado | Classe aplicada |
| --- | --- |
| `isExpanded` ou `isHovered` | `lg:ml-[290px]` |
| Recolhida | `lg:ml-[90px]` |
| `isMobileOpen` | `ml-0` |

A transição é `transition-all duration-300 ease-in-out`. O conteúdo é limitado por `max-w-(--breakpoint-2xl)` com padding crescente por breakpoint (`p-4 md:p-6 xl:p-8 2xl:p-10`).

### Regra de cliente inativo

`LayoutContent` faz uma verificação global de status sempre que há usuário com `role === 'client'`:

<Steps>
  <Step title="Descobre o próprio cliente">
    `GET /api/v1/client/list/` e então `findOwnClient(toClientList(raw), user.id)` (`src/utils/clients`).
  </Step>
  <Step title="Busca o status real">
    `GET /api/v1/client/retrieve/{id}/` e guarda `detail.active` em `isClientActive`.
  </Step>
  <Step title="Prende o cliente inativo no dashboard">
    Se `active` for falso, qualquer rota diferente de `homePathFor(user)` redireciona para o próprio início, onde o aviso de bloqueio é exibido.
  </Step>
</Steps>

<Note>
  A checagem roda no layout, não por rota, então vale para toda a área `/app` de uma vez. Se a chamada falhar, o cliente segue considerado ativo. Quem barra o acesso aos dados é a Plataforma.
</Note>

## Tema claro e escuro

`src/context/ThemeContext.tsx` implementa o tema com três peças:

| Peça | Comportamento |
| --- | --- |
| Estado | `theme: "light" \| "dark"`, começando em `light` |
| Persistência | `localStorage` na chave `theme`, lida em um `useEffect` no cliente |
| Aplicação | Adiciona ou remove a classe `dark` em `document.documentElement` |

API exposta:

```tsx
const { theme, toggleTheme } = useTheme();
```

- `theme` — tema corrente.
- `toggleTheme()` — alterna entre claro e escuro.
- `useTheme()` lança erro se usado fora de `ThemeProvider`.

<Tip>
  A escrita no `localStorage` só acontece depois de `isInitialized`, para não sobrescrever a preferência salva com o valor padrão no primeiro render.
</Tip>

No CSS, o modo escuro é uma variante customizada do Tailwind 4 em `src/index.css`:

```css
@custom-variant dark (&:is(.dark *));
```

Ou seja: qualquer utilitário prefixado com `dark:` responde à classe `dark` colocada na raiz pelo `ThemeContext`.

## Tokens de design

`src/index.css` concentra os tokens do design system no bloco `@theme` do Tailwind 4.

### Tipografia

Fonte **Outfit**, importada do Google Fonts na camada base, exposta como `--font-outfit`. A diretiva `--font-*: initial` zera as famílias padrão do Tailwind, deixando só as do projeto.

Escala de títulos e textos declarada com altura de linha própria:

| Token | Tamanho / linha |
| --- | --- |
| `--text-title-2xl` | 72px / 90px |
| `--text-title-xl` | 60px / 72px |
| `--text-title-lg` | 48px / 60px |
| `--text-title-md` | 36px / 44px |
| `--text-title-sm` | 30px / 38px |
| `--text-theme-xl` | 20px / 30px |
| `--text-theme-sm` | 14px / 20px |
| `--text-theme-xs` | 12px / 18px |

Há ainda as famílias de acento em amarelo (`--color-miggo-yellow-*`) e as bases `--color-black: #1d1d1b`, `--color-white`, `--color-current`, `--color-transparent`.

### Paleta por marca

Em domínio de agência a paleta muda em tempo de execução: `applyMarca` (`src/utils/marca.ts`), chamada pelo `MarcaContext`, sobrescreve as variáveis `--color-brand-*` no `<html>` com a escala da agência; `clearMarca` volta à da Miggo. Por isso as classes `brand-*` já acompanham a marca. Gráficos e SVG que não usam classe Tailwind leem a cor em vigor com `corDaMarca()` ou `corDoGrafico()`.

<Warning>
  Use os tokens, não hex solto no JSX. Cor escrita à mão não acompanha o tema escuro nem a paleta da agência.
</Warning>

### Utilitários de menu

`src/index.css` também declara utilitários próprios com `@utility` para a navegação da sidebar, em pares ativo/inativo:

`menu-item`, `menu-item-active`, `menu-item-inactive`, `menu-item-icon`, `menu-item-icon-active`, `menu-item-icon-inactive`, `menu-item-icon-size`, `menu-item-arrow`, `menu-item-arrow-active`, `menu-item-arrow-inactive`, `menu-dropdown-item`, `menu-dropdown-item-active`, `menu-dropdown-item-inactive`, `menu-dropdown-badge`, `menu-dropdown-badge-active`.

Ao adicionar item de menu, reaproveite esses utilitários em vez de repetir as classes.

## Ícones

`src/icons/` reúne os SVGs do app, importados como componentes React pelo **vite-plugin-svgr** (configurado em `vite.config.ts`). `src/icons/index.ts` reexporta cada um como componente nomeado; a tipagem vem de `src/svg.d.ts`.

```tsx
import { AlertIcon, PlusIcon } from "../icons";
```

Como o SVG vira componente, ele aceita `className` e herda `currentColor` — o que faz o ícone acompanhar o tema sem variante extra.
