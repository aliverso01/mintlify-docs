Todas as rotas são declaradas em `src/App.tsx` com `react-router` 7. As telas são carregadas sob demanda (`lazy`), para a rota pública não baixar o bundle do admin. Os paths são em inglês. A lista completa de rotas está em [Telas e rotas](/web/paginas).

## Três áreas, uma por perfil

| Área | Quem entra | Guard | Helper em `src/routes/rolePaths.ts` |
|---|---|---|---|
| `/admin/*` | Equipe Miggo: `role` `admin` ou `manager`, `is_staff` ou `is_superuser` | `ManagementRoute` | `isManagementUser` |
| `/agency/*` | Agência: `role` `agencia_admin` ou `agencia_membro` | `AgencyRoute` | `isAgencyUser` |
| `/app/*` | Cliente (e qualquer papel inesperado) | `ClientRoute` | `isClientUser` |

As áreas são mutuamente exclusivas. A raiz `/` não tem tela: `RoleHomeRedirect` manda cada usuário para a home da própria área (`homePathFor`).

Dentro do `/admin` há dois recortes a mais:

- **Admin pleno** (`isFullAdminUser`: `is_superuser` ou `role === "admin"`). O gestor não é admin pleno. Hoje só `/admin/agencies` exige isso, pelo `AdminRoute`.
- **Módulos.** `ModuloRoute modulo="..."` libera a tela se `temModulo(user, modulo)` (`src/routes/modulos.ts`, espelho de `app/account/modulos.py` da Plataforma). Admin e superusuário têm todos os módulos; `agencia_admin` tem `clientes`, `conteudo`, `membros`, `plano` e `marca`; gestor e membro de agência dependem da lista `modulos` do usuário. Veja [Área administrativa](/web/area-admin).

<Warning>
Guard é navegação, não autorização. Esconder a rota ou o botão não impede a chamada: a Plataforma e o MiggoAI recusam por endpoint (`401`/`403`). Toda tela nova depende dessa recusa no backend.
</Warning>

## Cadeia de guards

```text
ProtectedRoute                       exige login; sem sessão → /signin?next=<rota>
├── /grid/aprovar, /onboarding/conectado/..., /, rotas legadas
└── OnboardingGuard                  cliente com onboarding incompleto → /onboarding
    └── SubscriptionGuard            cliente sem assinatura ativa → tela de bloqueio
        └── AppLayout                sidebar, header, providers de layout
            ├── ManagementRoute      /admin/*
            │   ├── ModuloRoute      telas por módulo
            │   └── AdminRoute       /admin/agencies
            ├── AgencyRoute          /agency/*
            │   └── ModuloRoute
            └── ClientRoute          /app/*
```

| Guard | Regra |
|---|---|
| `ProtectedRoute` | Sem `user`, redireciona para `/signin?next=<pathname+search>`; o login volta para lá. |
| `OnboardingGuard` | Só filtra `role === "client"`. Libera as rotas de onboarding, planos e checkout. Com assinatura ativa, deixa passar mesmo sem onboarding concluído (assinatura criada pelo admin). Sem isso, manda para `/onboarding` se o onboarding não terminou e não foi pulado (`onboarding_skipped`). |
| `SubscriptionGuard` | Só filtra clientes. Sempre libera `/app/plans`, `/app/billing`, `/app/subscription/*`, `/app/profile` e `/app/support`. Sem assinatura ativa, mostra a tela de bloqueio com o caminho para assinar ou abrir o portal de cobrança. Com pagamento pendente (`UNPAID`), mostra um aviso e libera. |
| `ManagementRoute` | Quem não é equipe Miggo volta para a própria área. |
| `AgencyRoute` | Quem não é agência volta para a própria área. |
| `ClientRoute` | Bloqueia por exclusão: agência vai para `/agency/clients`, equipe Miggo vai para `/admin`. Assim um papel desconhecido cai em `/app` em vez de entrar em loop de redirect. |
| `AdminRoute`, `ModuloRoute` | Quem não passa volta para a home da área. |

Enquanto `useAuth().loading` é `true`, os guards de papel mostram `RouteLoader`.

## Montar links

Não escreva `/admin/content` ou `/app/content` no JSX: o mesmo componente serve a mais de uma área. Use o hook `useRoleArea`:

```tsx
const { path, isManagement } = useRoleArea();
<Link to={path("content")}>Conteúdos</Link>   // /admin/content, /agency/content ou /app/content
```

## Rotas públicas

`/signin`, `/reset-password`, `/onboarding` (a etapa 1 cria a conta), `/midia/:token` (download de mídia por link assinado, sem login), `/terms` e `/privacy`. `/signup` redireciona para `/onboarding`.

## Rotas legadas

As rotas raiz de antes da separação em áreas (`/content`, `/brandkit`, `/billing`, `/clients`, os retornos de OAuth `/instagram/success/...` etc.) continuam registradas em `src/routes/legacyPaths.ts` para não quebrar links salvos, e-mails já enviados e redirect URIs de OAuth. `LegacyPathRedirect` resolve o destino com `resolveLegacyPath`: na maioria, o mesmo subpath na área do usuário; `/clients` e `/users` só existem no admin, e `/subscription/*` só no cliente (quem não tem a tela vai para a home).

Rota nova nasce dentro de uma área. Não acrescente nada em `legacyPaths.ts`.
