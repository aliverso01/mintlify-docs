A suíte usa o runner do Django (`manage.py test`, classes `django.test.TestCase`). Não há pytest. Os testes ficam em `tests.py` ou em pastas `tests/` de cada app.

| App | Onde | Cobre |
|---|---|---|
| `generations` | `apps/generations/tests/` | workflows, contrato de saída, runner, rodada e lock, idempotência do grid, peças de perfil, fila e entrega, regeneração, galeria e banco de imagens, chamadas à OpenAI simuladas |
| `prompts` | `apps/prompts/tests/` | renderização e versionamento |
| `custos` | `apps/custos/tests/` | registro, preços, câmbio, agregados, estimativa retroativa e API do painel |
| `clients`, `common` | `tests.py`, `tests_listagem.py` | variáveis salvas, listagem de clientes e token da plataforma |
| `core` | `core/tests.py` | configuração do Celery (sem Redis: URL fictícia) |

As chamadas à OpenAI e ao `backend-miggo` são simuladas com `unittest.mock`; nenhum teste chama os serviços de verdade.

## Rodar

As settings exigem as mesmas variáveis do servidor, então rode de `backend/` com o `.env` preenchido.

<Tabs>
  <Tab title="PostgreSQL">
    O usuário do banco precisa de permissão para criar o banco de teste (`CREATEDB`).

    ```bash
    cd miggoai-2.0/miggoai_v2/backend
    python manage.py test                    # suíte inteira
    python manage.py test apps.prompts       # um app
    python manage.py test apps.generations.tests.test_grid_workflow
    ```
  </Tab>
  <Tab title="SQLite em memória">
    Quando o usuário do Postgres local não pode criar o banco de teste, troque só o banco por um settings que importa `core.settings` e define `DATABASES` com `sqlite3` em `:memory:`. Crie o arquivo fora do repositório (ou num caminho ignorado pelo git):

    ```python test_settings.py
    from core.settings import *  # noqa: F401,F403

    DATABASES = {
        'default': {
            'ENGINE': 'django.db.backends.sqlite3',
            'NAME': ':memory:',
        }
    }
    ```

    Rode com a pasta do arquivo no `PYTHONPATH`:

    ```bash
    cd miggoai-2.0/miggoai_v2/backend
    PYTHONPATH=/caminho/da/pasta python manage.py test apps.prompts --settings=test_settings
    ```

    O mesmo arquivo serve à Plataforma: veja [Testes da Plataforma](/plataforma/testes).
  </Tab>
</Tabs>

## Verificações além da suíte

```bash
python manage.py check
python manage.py makemigrations --check --dry-run   # nenhuma migration pendente
python manage.py celery_ping                         # só com Redis e worker no ar
```

## Teste manual de geração

Para ver uma geração de ponta a ponta sem tocar em produção, use o ambiente `TEST` pelo [painel de IA](/web/painel-de-ia) ou pela API (`POST /api/generations/test/complete/`). As imagens de teste ficam em `generations/test/` e podem ser apagadas com `python manage.py cleanup_test_generations`.
