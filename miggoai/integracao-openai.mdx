Toda chamada à OpenAI sai de `backend/apps/generations/services/openai_service.py`, com exceção do grid, que tem o próprio cliente em `grid_workflow.py` com as mesmas regras. A chave é `OPENAI_API_KEY`, enviada como `Authorization: Bearer`. As chamadas usam `requests` direto, sem SDK.

## Endpoints usados

| Endpoint | Função | Usado por | Timeout |
|---|---|---|---|
| `POST /v1/chat/completions` | `chat_json` | título, legenda, hashtags, bio, seleção de microângulo, classificação de foto, intenção de ajuste do banner | 60 s |
| `POST /v1/images/edits` | `generate_image` | imagem do post (grid do cliente como referência) | 300 s |
| `POST /v1/images/edits` | `grid_workflow._recriar_referencia` | grid a partir de uma referência ou da peça anterior | 300 s |
| `POST /v1/images/generations` | `gerar_arte` | arte de fundo do banner do LinkedIn | 300 s |
| `POST /v1/images/generations` | `grid_workflow._gerar_do_zero` | grid sem referência | 300 s |

## Modelos

O modelo de cada workflow não é fixo no código: vem da `WorkflowConfig` (`text_model`, `image_model`, `temperature`, `max_tokens`), editável no [painel de IA](/web/painel-de-ia) por superusuário. Os defaults do model são `gpt-4o-mini` (texto) e `gpt-image-2` (imagem). Chamadas auxiliares com prompt fixo, como o `media_classifier`, usam `gpt-4o-mini`.

Trocar o modelo para um que não tem `PrecoModelo` cadastrado é permitido; a API devolve o aviso em `modelos_sem_preco` e as chamadas ficam com `sem_preco=True` no custo (ver [Custos de IA](/miggoai/custos)).

## Texto: `chat_json`

```python
chat_json(prompt, model='gpt-4o-mini', temperature=0.7, max_tokens=2000, schema=None) -> dict
```

- **Mensagens:** duas de sistema (papel de copywriter de social media brasileiro e "Responda sempre com JSON válido.") e o prompt renderizado do CMS como mensagem do usuário.
- **Formato da resposta:** com `schema`, `response_format` é `json_schema` com `strict: true`, montado pelo contrato de saída (`output_contract.py`); sem `schema`, `json_object`.
- **`max_tokens`** vai como `max_completion_tokens`. Nos modelos de raciocínio o limite inclui os tokens de raciocínio.
- **`temperature`** só é enviada para modelos `gpt-4*` e `gpt-3.5*`. Os modelos de raciocínio aceitam só o default.
- **Nunca levanta exceção.** Erro de rede, HTTP ou parse volta como `{"error": "..."}`; o workflow decide o que fazer.

Fallbacks em `400`, cada um tentado uma única vez:

| A OpenAI recusou | O que acontece |
|---|---|
| `temperature` | repete sem `temperature` |
| `response_format` / `json_schema` | repete com `json_object` |
| outro parâmetro | devolve `{"error": "Erro OpenAI 400: ..."}` |

Resposta vazia cortada por `finish_reason == "length"` vira erro explícito. JSON envolvido em bloco de código ou com texto em volta é extraído antes de desistir.

## Imagem do post: `generate_image`

```python
generate_image(prompt, grid_url, gen_size, model='gpt-image-2', extra_reference_urls=None) -> bytes
```

- **Referências:** o grid do cliente vai sempre em `images[0]`; foto da galeria ou do banco de imagens, logo e referência de design entram como extras.
- **Payload:** `quality: "high"`, `output_format: "png"`, `n: 1`, `size` pelo formato.
- **Tamanhos**, já na proporção de entrega (sem corte nem reamostragem):

| Formato | Tamanho |
|---|---|
| `story`, `reel` | `1152x2048` (9:16) |
| `feed`, `carrossel` | `1088x1360` (4:5) |

Antes da chamada, cada referência é conferida:

- extensão que a API não lê (`.svg`, `.gif`, `.pdf`, …) é descartada;
- URL que não responde (ex.: `404`) sai do payload; o resultado da checagem fica em cache por 5 minutos;
- host local ou de rede privada, que a OpenAI não alcança, é baixado e enviado como data URL (até 12 MB) **só com `DEBUG`**; em produção é recusado. Cada redirect é revalidado (no máximo 3).

Se a OpenAI recusar mesmo assim:

| Erro | Reação |
|---|---|
| `invalid_image_file` numa referência extra | repete uma vez sem aquela referência |
| falha ao baixar uma URL (não diz qual) | repete uma vez só com o grid |
| grid inacessível | falha antes de chamar, sem gastar a chamada |
| qualquer outro | `RuntimeError` com mensagem para o usuário |

## Arte de fundo: `gerar_arte`

`images/generations`, sem referência, `1024x1024`, `quality: "medium"`. Serve ao banner do LinkedIn, que é composto depois em HTML. As capas de destaque não usam IA.

## Grid do onboarding

`grid_workflow.py`, quadrado `1024x1024`, modelo padrão `gpt-image-2`:

- **com referência:** `images/edits` recriando o molde com a paleta e o logo do cliente; `input_fidelity: "high"` só para `gpt-image-1` (a família `gpt-image-2` recusa o parâmetro);
- **modo correção** (`peca_anterior_url` + `feedback`): edita a peça anterior; se a OpenAI recusar a base, cai no modo referência;
- **sem referência:** `images/generations` com `quality: "high"`.

## Recusa de conteúdo (moderação)

A OpenAI recusa com `code: "moderation_blocked"` ou com a mensagem "rejected by the safety system".

| Onde | Resultado |
|---|---|
| Imagem do post | `RuntimeError` com "A imagem foi recusada pelo filtro de segurança do provedor. Ajuste o texto do card e tente novamente." |
| Grid | `GridRecusadoPorConteudo`; a `Generation` grava `result = {"error_kind": "content_policy"}` e a API responde `422`. A mesma `idempotency_key` passa a responder `422` sem chamar a OpenAI. |

Recusa de moderação nunca é retentada pela fila.

## Mensagens de erro

O usuário vê só frases do MiggoAI:

| Constante | Quando |
|---|---|
| `MENSAGEM_FALHA_IMAGEM` | falha genérica da imagem |
| `MENSAGEM_FALHA_REFERENCIA` | grid, logo, foto ou referência inacessível |
| `MENSAGEM_FALHA_MODERACAO` | recusa do filtro de segurança |

O corpo de erro da OpenAI vai só para o log, e URLs assinadas são logadas sem a query (que carrega a credencial).

## Retentativa

`openai_service` não repete por conta própria fora dos fallbacks acima. A repetição automática existe só nas tasks do Celery e só para falha transitória (`grid_workflow.eh_falha_transitoria`): erro de conexão, `429` e `5xx`. Read timeout **não** é repetido: depois de 300 s a OpenAI pode ter gerado e cobrado.

## Registro de custo

Toda resposta com sucesso chama `apps.custos.services.registro.registrar_resposta(modelo, operacao, corpo, imagens=...)`, que grava uma `ChamadaIA` com os tokens do campo `usage`, o custo em dólar pela `PrecoModelo` e a etapa corrente da auditoria. O registro **nunca levanta exceção**: perder o custo é ruim, perder a geração por causa dele seria pior. Detalhes em [Custos de IA](/miggoai/custos).
