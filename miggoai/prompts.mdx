O app `apps.prompts` é o CMS que guarda o **conteúdo editável** dos prompts de IA — nome do cliente, briefing, regras de tom de voz, tarefa. A **forma da resposta** (JSON, quais chaves) nunca passa por aqui: é fixa no código (`apps.generations.services.output_contract`, ver [Workflows](/miggoai/workflows)).

<Note>
A forma da resposta é fixa no código; o CMS só edita conteúdo. Não escreva formato de saída nem exemplo de JSON no prompt.
</Note>

## Estrutura de dados

Ver models completos em [Modelo de dados](/miggoai/modelo-de-dados). Resumo funcional:

- **`Workflow`** — um tipo de geração: `title`, `image`, `caption`, `hashtags`, `banner`, `destaques`, `grid`, `bio`. Tem uma `WorkflowConfig` (modelo de IA, temperatura, `max_tokens`).
- **`PromptDefinition`** — o template em si, identificado por `slug` único. Um workflow pode ter mais de um prompt (o de `title` tem 3: `titulo-story`, `titulo-feed`, `titulo-carrossel`).
- **`PromptVariable`** — declaração das chaves `{{...}}` aceitas pelo template, com `label`, `default_value` e `required`.
- **`PromptVersion`** — snapshot do conteúdo anterior, criado automaticamente a cada `PUT` que muda `content` e a cada restauração de versão. As duas operações passam por `apps/prompts/services/versionamento.py::trocar_conteudo`, que arquiva o texto atual com número acima do último já arquivado e nunca reescreve o histórico.

## Renderização (`apps/prompts/services/rendering.py`)

Módulo puro (sem I/O, sem chamada a IA), usado tanto pela API de preview quanto pelos workflows reais.

### `extract_variables(template: str) -> list[str]`

Devolve as chaves `{{chave}}` do template, na ordem de aparição, sem duplicatas. Regex: `\{\{\s*([a-zA-Z_][a-zA-Z0-9_]*)\s*\}\}`.

### `render(template, values, required_keys=None) -> str`

Substitui cada `{{chave}}` pelo valor correspondente em `values`.

- Se `required_keys` é passado, valida que cada chave existe em `values` E, se for string, não é vazia após `strip()` — senão levanta `MissingVariableError(missing_keys)`.
- Valores não-string "falsy" (`0`, `[]`, `False`) contam como presentes — só strings vazias/ausentes disparam o erro.
- Chave sem valor correspondente vira string vazia (não levanta erro fora do required).

```python
render("Olá {{nome}}", {"nome": "Ana"})
# "Olá Ana"

render("{{a}} {{b}}", {"a": "x"}, required_keys=["b"])
# levanta MissingVariableError(['b'])
```

### `diff_variables(template, stored_keys) -> dict`

Compara as chaves do template atual com as `PromptVariable` já cadastradas — usado pelo endpoint `detect-variables`.

```python
{
    "new": [...],       # no template, ainda sem PromptVariable
    "removed": [...],   # PromptVariable cadastrada, sumiu do template
    "unchanged": [...],
}
```

## Como o contrato de saída se conecta ao prompt

`output_contract.CONTRACT_BY_SLUG` mapeia cada `slug` de prompt a um contrato fixo:

```python
CONTRACT_BY_SLUG = {
    'titulo-story': TITULO_TEXTO,
    'titulo-feed': TITULO_TEXTO,
    'titulo-carrossel': TITULO_CARDS,
    'legenda-post': LEGENDA,
    'hashtags-post': HASHTAGS,
}
```

`imagem-post` e `banner-linkedin-arte` não têm contrato — a resposta da OpenAI para imagem não é JSON. `output_contract.apply(key, rendered_prompt)` concatena o `content` renderizado do CMS com o bloco de instrução fixo e devolve também o `schema` JSON usado como `response_format` na chamada à OpenAI (structured output, `strict: True`). Ver detalhes em [Workflows](/miggoai/workflows).

## Como editar um prompt

1. **Painel de IA** no `/admin` do `frontend-miggo` (`/admin/miggoai/prompts`): edição com preview do rascunho ainda não salvo, detecção de variáveis, histórico com restauração e o autor da última edição (`editado_por`). Ver [Painel de IA](/web/painel-de-ia).
2. **API**: `PUT /api/prompts/<id>/` com `{"content": "...", "change_note": "..."}` versiona o conteúdo anterior; `POST /api/prompts/<id>/versions/<n>/restore/` restaura uma versão como versão nova, sem apagar histórico; `POST /api/prompts/<id>/preview/` renderiza com `values` (e, opcionalmente, um `content` de rascunho) sem chamar IA.
3. **Seed versionado**: editar `backend/apps/prompts/data/seed_prompts.json` e rodar `python manage.py seed_prompts`. Idempotente, casa por chave natural (`slug`/`key`), roda a cada subida do container web.

Config de modelo do workflow (`PATCH /api/prompts/workflows/<id>/`: `text_model`, `image_model`, `temperature` de 0 a 2, `max_tokens` de 1 a 128000) só por superusuário.

<Warning>
  `seed_prompts` nunca apaga variáveis órfãs por padrão — use `--prune-variables` explicitamente se quiser remover do
  banco variáveis que saíram do seed. Sem essa flag, variáveis removidas do JSON
  continuam no banco.
</Warning>

## Ativação/desativação

`is_active=False` em um `PromptDefinition` faz o workflow correspondente falhar com `PromptDefinition.DoesNotExist` na hora de gerar — os workflows sempre buscam com `is_active=True` . Use `POST .../activate/` e `POST .../deactivate/` para alternar sem apagar o conteúdo.
