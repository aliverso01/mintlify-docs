**POST `/api/generations/gerar-agora/`** e **POST `/api/generations/gerar-card/`** — disparo fora da rodada diária (MIG-379)

Rodam a mesma rotina do cron (`services.rodada`), então a execução manual produz o mesmo resultado da automática. Respondem **`202` e trabalham em thread**: o resultado aparece no painel de gerações, nunca nesta requisição.

<ParamField path="client_id" type="integer" required>Id do cliente no `backend-miggo`. Obrigatório nos dois endpoints.</ParamField>
<ParamField path="post_id" type="integer" required>Só em `gerar-card/`: id do card a processar.</ParamField>
<ParamField path="extra_days" type="integer">Só em `gerar-agora/`: dias extras de antecedência na busca do card. Default `0`.</ParamField>
<ParamField path="limit" type="integer">Só em `gerar-agora/`: teto de cards da rodada. Default sem limite.</ParamField>

<ResponseField name="status" type="string">`aceito` — o lock da rodada foi tomado e a geração começou nesta chamada. `na_fila` — já havia rodada em andamento, o pedido **não** foi tomado e fica para a próxima passada do cron.</ResponseField>
<ResponseField name="client_id" type="integer">Ecoa o cliente pedido.</ResponseField>
<ResponseField name="post_id" type="integer">Só em `gerar-card/`: ecoa o card pedido.</ResponseField>

```json
{"client_id": 42, "status": "aceito"}
{"post_id": 5409, "client_id": 42, "status": "na_fila"}
```

<Warning>
  **Decida pelo `status` do corpo, nunca pelo código HTTP.** Os dois desfechos são `202` de propósito: adiar é desfecho normal, não falha de disparo, e um não-2xx seria auditado e logado como erro no `backend-miggo` — mentira. Quem consome trata `aceito` como "começou agora" e **qualquer outra coisa** (`na_fila`, campo ausente, corpo que não é dict, valor desconhecido) como "ficou para o cron"; é o que o `backend-miggo` faz ao traduzir em `disparo` (ver <a href="/backend/apps/client">app client</a>).
</Warning>

Os dois só tomam o lock na thread da requisição — é a única forma de a resposta saber o desfecho. `400` quando falta `client_id` (ou `post_id`), ou quando não são números.

**POST `/api/generations/grid/`**
<ParamField path="client_id" type="integer" required>Id do cliente no backend-miggo — é a quem o registro `Generation` fica pendurado.</ParamField>
<ParamField path="cores" type="array">Lista de hex da paleta (`400` se não for lista de strings).</ParamField>
<ParamField path="nicho" type="string" />
<ParamField path="descricao_referencia" type="string" />
<ParamField path="feedback" type="string">Pedido de ajuste do cliente.</ParamField>
<ParamField path="referencia_url" type="string">Referência de estilo. Sem ela o grid é gerado do zero.</ParamField>
<ParamField path="logo_url" type="string" />
<ParamField path="peca_anterior_url" type="string">O grid que o cliente já viu e pediu para ajustar — com `feedback`, seleciona o modo correção.</ParamField>
<ParamField path="idempotency_key" type="string">Opcional, máximo 64 caracteres (`400` acima disso). Identifica **uma geração lógica**: repetição por retry/timeout reusa a mesma chave (MIG-427).</ParamField>

<ResponseField name="200 OK" type="object">`{image_b64, generation_id, reused}`. `reused: true` quando a peça já existia para aquela chave — **não gerou nem cobrou de novo**.</ResponseField>
<ResponseField name="409 Conflict" type="object">`{status, generation_id, detail}` — a geração daquela chave está `PENDING`/`RUNNING`. Não inicia outra: é a trava que evita a segunda cobrança.</ResponseField>
<ResponseField name="502 Bad Gateway" type="object">`{error, generation_id}` — a peça não saiu (`FAILED` ou geração sem imagem). É "não produziu", não "pedido errado".</ResponseField>

O que a chave faz em cada estado:

| Estado da chave no MiggoAI | Comportamento |
|---|---|
| sem `idempotency_key` no corpo | igual a antes da MIG-427 — gera e cobra (compat com chamador antigo) |
| inexistente | gera, cobra e grava a chave na `Generation`; `reused: false` |
| `SUCCESS` | devolve a peça já gerada, `reused: true`, **sem gerar nem cobrar** |
| `PENDING`/`RUNNING` | `409`, sem iniciar outra |
| `FAILED` | re-executa sob a **mesma** `Generation` (a chave é unique); só cobra se concluir |
| de outro `client_id` | `400` — a chave é de uma geração de um cliente só |

Corrida entre duas chamadas com a mesma chave: o `unique` do banco é a guarda final; o `IntegrityError` é capturado e devolve o estado do registro que ganhou (nada foi gerado nem cobrado no perdedor).

#### Estrutura do bloco `custo`
Consolida as chamadas (`ChamadaIA`) da geração ou dos passos da execução:
- `usd`: string decimal com 6 casas (`0.000000`).
- `brl`: string decimal com 2 casas ou `null` caso não haja cotação. Convertido via `cambio.taxa_vigente()`, lendo a cotação mais recente gravada no banco local sem chamadas HTTP externas durante o polling de 2 s.
- `estimado`: booleano (`true` se alguma chamada usou precificação estimada).
- `sem_preco`: booleano (`true` se algum modelo chamado não possuía tabela de preço cadastrada).
- `chamadas`: número inteiro de chamadas de IA. Quando `chamadas === 0`, indica que não houve consumo medido (a tela exibe "—" para não apresentar um zero falso).

**GET `/api/generations/execucoes/<pk>/`**

Retorna os detalhes de uma execução com seus passos aninhados (`ExecucaoSerializer`), acrescido de:
- `custo`: bloco consolidado com o custo total da execução (`{usd, brl, estimado, sem_preco, chamadas}`).
- `custo_por_etapa`: array `[{generation_id, etapa, usd, brl, estimado, sem_preco, chamadas}]` com a discriminação dos custos de cada passo na ordem em que rodaram.
