A API do MiggoAI é REST + JSON, servida pelo Django REST Framework. Cada endpoint está na referência gerada do OpenAPI, nesta mesma aba, agrupada por recurso (Gerações, Prompts, Custos, Clientes, Posts, Token).

## Base URL

| Ambiente | URL |
|---|---|
| Produção | `https://backend-ai.miggomkt.com.br` |
| Local | `http://localhost:8010` |

Homologação roda em serviço e banco próprios no Dokploy (ver [Ambientes](/arquitetura/ambientes)). Todas as rotas ficam sob `/api/`, sem versão no caminho. Fora dela só há `/health/` (sem autenticação, para o healthcheck) e `/admin/` (Django admin).

| Prefixo | Recurso |
|---|---|
| `/api/generations/` | gerar, consultar e apagar gerações; grid, perfil, rodada, regeneração |
| `/api/prompts/` | workflows, prompts, versões e variáveis |
| `/api/custos/` | dashboard, preços, cotações e log de chamadas |
| `/api/clients/` | clientes da plataforma (proxy) e variáveis salvas |
| `/api/posts/` | posts, formatos e status da plataforma (proxy) |
| `/api/token/` | token local (SimpleJWT) |

## Autenticação

Toda rota exige credencial, exceto `/health/` e `/api/token/`:

```bash
curl https://backend-ai.miggomkt.com.br/api/generations/resumo/ \
  -H "Authorization: Bearer $ACCESS_DA_PLATAFORMA"
```

Token da plataforma (painel), `Api-Key` (backend-miggo) ou token local: ver [Autenticação](/miggoai/autenticacao).

## Erros

Erros de validação e de negócio voltam como `{"error": "<mensagem>"}`; erros do DRF (autenticação, permissão) como `{"detail": "<mensagem>"}`.

| Status | Significado |
|---|---|
| `400` | Corpo ou query inválidos: campo obrigatório ausente, tipo errado, `idempotency_key` com mais de 64 caracteres ou de outro cliente. |
| `401` / `403` | Credencial ausente ou inválida / sem permissão. Ver [Autenticação](/miggoai/autenticacao#erros). |
| `404` | Recurso inexistente. Nas rotas `by-key`, chave desconhecida e chave de outro cliente dão o mesmo `404`. |
| `409` | Já existe geração `PENDING`/`RUNNING` para aquela `idempotency_key` (grid síncrono). Não inicia outra. |
| `422` | `error_kind: "content_policy"`: a OpenAI recusou o pedido pelo filtro de segurança. Repetir o mesmo pedido será recusado de novo; só um pedido alterado (chave nova) gera outra vez. |
| `502` | A peça não saiu (geração `FAILED`), ou o `backend-miggo` não respondeu. É "não produziu", não "pedido errado". O corpo traz `generation_id` quando há registro. |

Mensagens de falha de imagem são frases do MiggoAI ("Não foi possível gerar a imagem agora…"); o corpo da OpenAI fica só no log.

## Paginação

As listas paginadas aceitam `?page=` (padrão 1) e `?page_size=` (padrão 50, teto 200).

| Rota | Envelope |
|---|---|
| `GET /api/generations/`, `GET /api/generations/linhas/` | `{count, page, total_pages, results}` |
| `GET /api/custos/cotacoes/`, `/precos/`, `/chamadas/` | `{count, page, page_size, results}` |

As demais listas (prompts, workflows, clientes, posts) voltam sem envelope. As de cliente e post repassam o que o `backend-miggo` devolve.

Não há limite de requisições (rate limit) no serviço.

## Operações demoradas: 202 e polling

Gerar leva de segundos a minutos (uma imagem pode levar até 300 s). Por isso vários endpoints respondem `202` e o resultado é consultado depois:

| Disparo | Resposta | Como acompanhar |
|---|---|---|
| `POST gerar-agora/`, `POST gerar-card/` | `202 {status: "aceito" \| "na_fila"}` | lista de gerações (`linhas/`) ou o próprio post na plataforma |
| `POST regenerate/` | `202 {since_id, ...}` | `GET regenerate/status/?post_id=&target=&since_id=` até `success` ou `failed` |
| `POST grid/` com fila | `202 {status, generation_id}` | `GET grid/by-key/<chave>/?client_id=` |
| `POST perfil/{bio,banner,destaques}/` com fila | `202 {status, generation_id}` | `GET perfil/by-key/<chave>/?client_id=` |

Em `gerar-agora/` e `gerar-card/`, decida pelo `status` do corpo, não pelo código HTTP: os dois desfechos são `202`. Durante a execução, `Generation.stage` traz o estágio em texto ("Gerando imagem 2/3").

## Idempotência

Grid e peças de perfil aceitam `idempotency_key` (até 64 caracteres). Ela identifica **uma** geração lógica: repetir o pedido com a mesma chave devolve a peça já gerada (`reused: true`) sem gerar nem cobrar de novo, ou `409`/`202` se ela ainda estiver em andamento. Geração parada há mais de 15 minutos é considerada órfã e marcada `FAILED` na próxima consulta. Detalhes em [Gerar conteúdo](/miggoai/guias/gerar-conteudo#grid-do-onboarding).
