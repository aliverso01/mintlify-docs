## Backend e MiggoAI (Django)

| Regra | Detalhe |
| --- | --- |
| Migrations | Toda alteração de model exige `makemigrations` + `migrate`. Não edite migrations já aplicadas em produção. |
| Verificação antes de concluir | `./venv/Scripts/python.exe manage.py check` precisa passar. |
| Testes | O banco de teste pode falhar por permissão no Postgres local. Quando `manage.py test` não conseguir criar o banco, valide com `manage.py check` mais um import isolado do módulo alterado. Veja [Testes](/backend/testes). |
| Organização do app | Siga a anatomia já usada pelos apps existentes (models, serializers, views, urls, services). Veja [Estrutura](/backend/estrutura). |
| Auditoria de chamadas externas | Toda chamada a terceiro deve registrar em `Integration`, de forma *best-effort* — falhar a auditoria nunca pode derrubar o fluxo real. |

## Frontend (React 19 + TypeScript)

| Regra | Detalhe |
| --- | --- |
| TypeScript estrito | Nenhum `any` novo. Tipos explícitos em props, retornos de hooks e respostas de API. |
| Lint obrigatório | `npm run lint` sem erros antes de concluir. |
| Build verifica tipos | `npm run build` roda `tsc -b` antes do Vite — um build verde é a garantia de tipagem. |
| Componentes | Funcionais com hooks. Reaproveite os componentes existentes antes de criar novos. |
| Rotas por papel | Respeite a separação `/app` (cliente) e `/admin` (equipe). Veja [Roteamento](/frontend/roteamento). |

## Prioridades de revisão de código

Correção antes de estilo. Na ordem:

1. **Correção** — faz o que promete? Casos de borda, `null`/`undefined`, erros silenciados.
2. **Segurança** — entrada não validada, injeção, dado sensível em log, permissão e autorização.
3. **Regressão** — quebra algo existente? Atenção especial aos contratos de API entre os três repositórios.
4. **Simplicidade e reuso** — dá para usar o que já existe? Há duplicação?
5. **Testes** — o caminho crítico está coberto?

Reporte achados no formato `arquivo:linha` — problema — correção sugerida.

## Contratos entre repositórios

Mudar o formato de uma resposta da API do backend quebra o frontend e possivelmente o MiggoAI. Antes de alterar um serializer ou uma rota:

- Procure os consumidores no `frontend-miggo` (`src/services/`, `src/hooks/`).
- Verifique se o MiggoAI depende do campo (`modules/miggo.py` no repositório do MiggoAI).
- Prefira adicionar campos a renomear ou remover; quando remover for inevitável, faça em duas etapas.
