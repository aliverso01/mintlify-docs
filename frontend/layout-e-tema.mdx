## A casca: `AppLayout`

`src/layout/AppLayout.tsx` é o componente que envolve **todas** as telas autenticadas. Ele monta os providers de layout e o esqueleto visual:

```
AppLayout
├── SidebarProvider          (estado da sidebar)
│   └── SearchProvider       (busca global)
│       ├── LayoutContent
│       │   ├── AppSidebar + Backdrop
│       │   └── coluna principal
│       │       ├── AppHeader
│       │       └── <Outlet />   ← a tela da rota
│       │   └── SupportChatWidget
│       └── PreviewModeBanner
```

| Arquivo | Responsabilidade |
| --- | --- |
| `src/layout/AppLayout.tsx` | Providers, esqueleto e a regra de cliente inativo |
| `src/layout/AppSidebar.tsx` | Menu lateral e navegação |
| `src/layout/AppHeader.tsx` | Cabeçalho: busca, tema, perfil |
| `src/layout/Backdrop.tsx` | Fundo escurecido quando a sidebar abre no mobile |
| `src/layout/SidebarWidget.tsx` | Bloco promocional/informativo no pé da sidebar |

### Deslocamento da coluna principal

A margem esquerda do conteúdo reage ao estado da sidebar, lido de `useSidebar()`:

| Estado | Classe aplicada |
| --- | --- |
| `isExpanded` ou `isHovered` | `lg:ml-[290px]` |
| Recolhida | `lg:ml-[90px]` |
| `isMobileOpen` | `ml-0` |

A transição é `transition-all duration-300 ease-in-out`, e o conteúdo é limitado por `max-w-(--breakpoint-2xl)` com padding crescente por breakpoint (`p-4 md:p-6 xl:p-8 2xl:p-10`).

### Regra de cliente inativo

`LayoutContent` faz uma verificação global de status sempre que há usuário com `role === 'client'`:

<Steps>
  <Step title="Descobre o próprio cliente">
    `GET /api/v1/client/list/` e então `findOwnClient(toClientList(raw), user.id, isPreviewMode)` (`src/utils/clients`).
  </Step>
  <Step title="Busca o status real">
    `GET /api/v1/client/retrieve/{id}/` e guarda `detail.active` em `isClientActive`.
  </Step>
  <Step title="Prende o cliente inativo no dashboard">
    Se `active` for falso, qualquer rota diferente de `homePathFor(user)` redireciona para o próprio início, onde o aviso de bloqueio é exibido.
  </Step>
</Steps>

<Note>
  A checagem roda no layout, não por rota — então vale para toda a área `/app` de uma vez. Falha de rede é engolida com `console.error` e o cliente segue considerado ativo.
</Note>

## Tema claro e escuro

`src/context/ThemeContext.tsx` implementa o tema com três peças:

| Peça | Comportamento |
| --- | --- |
| Estado | `theme: "light" \| "dark"`, começando em `light` |
| Persistência | `localStorage` na chave `theme`, lida em um `useEffect` no cliente |
| Aplicação | Adiciona ou remove a classe `dark` em `document.documentElement` |

API exposta:

```tsx
const { theme, toggleTheme } = useTheme();
```

- `theme` — tema corrente.
- `toggleTheme()` — alterna entre claro e escuro.
- `useTheme()` lança erro se usado fora de `ThemeProvider`.

<Tip>
  A escrita no `localStorage` só acontece depois de `isInitialized`, para não sobrescrever a preferência salva com o valor padrão no primeiro render.
</Tip>

No CSS, o modo escuro é declarado como variante customizada do Tailwind 4 (`src/index.css:5`):

```css
@custom-variant dark (&:is(.dark *));
```

Ou seja: qualquer utilitário prefixado com `dark:` responde à classe `dark` colocada na raiz pelo `ThemeContext`.

## Ícones

`src/icons/` reúne 59 arquivos SVG, importados como componentes React pelo **vite-plugin-svgr** (configurado em `vite.config.ts`). A tipagem dos imports vem de `src/svg.d.ts`.

```tsx
import AlertIcon from "../icons/alert.svg?react";
```

Como o SVG vira componente, ele aceita `className` e herda `currentColor` — o que faz o ícone acompanhar o tema sem variante extra.
