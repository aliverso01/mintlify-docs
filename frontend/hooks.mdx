<Accordion title="useBrandkit — useBrandkits + funções soltas">
`src/hooks/useBrandkit.ts`

O arquivo exporta o hook `useBrandkits` mais um conjunto grande de funções assíncronas de CRUD (não são hooks React, são chamadas de API diretas). Ver a assinatura completa de cada uma em `services.mdx`, seção "Funções de `useBrandkit.ts`".

```ts
export const useBrandkits = (
  clientId?: number | null,
  isAdmin?: boolean
): { brandkits: Brandkit[]; loading: boolean; error: string | null; refetch: () => Promise<void> };
```

- `isAdmin=true` → `GET /api/v1/brandkit/list/` (com `?client_id=` se `clientId` também for passado).
- `isAdmin=false` → `GET /api/v1/brandkit/client/<clientId>/`, e só busca quando `clientId` está resolvido (`useBrandkit.ts:99-136`).

**Uso real** (`src/pages/Brandkit/useBrandkitPage.ts:84`):
```ts
const { brandkits, loading, error, refetch } = useBrandkits(clientId, isAdmin);
```

<Accordion title="useClient">
`src/hooks/useClient.ts:6-65`

```ts
export const useClient = (): { clientId: number | null; loading: boolean; error: string | null };
```

Sem parâmetros — resolve o `clientId` do usuário logado. Em preview mode, usa direto `previewClientId` do `PreviewContext`. Caso contrário, consulta `GET /api/v1/client/list/?user=<user.id>` e usa o primeiro resultado; guarda o resultado em `localStorage["client_id_<user.id>"]` como cache entre sessões (`useClient.ts:9-12,25-51`). Só dispara a busca se `user.role === 'client'`.

**Uso real** (`src/components/OnboardingGuard.tsx:15`):
```ts
const { clientId, loading: clientLoading } = useClient();
```
</Accordion>

<Accordion title="useClientPlatforms">
`src/hooks/useClientPlatforms.ts:76-146`

```ts
export function useClientPlatforms(clientId: number | string | null | undefined): {
  networks: ClientPlatform[];
  activeNames: string[];
  activeIds: number[];
  loading: boolean;
};
```

Deriva as redes sociais disponíveis para o cliente **a partir do nome do plano da assinatura ativa** (não da integração conectada) — assim o cliente vê as funcionalidades da rede que assinou mesmo antes de conectar a conta (`useClientPlatforms.ts:1-15`). Chama em paralelo:
- `GET /api/v1/post/social-network/list/`
- `GET /api/v1/post/platform-integration/list/?client=<clientId>`
- `GET /api/v1/subscription/list/?client_id=<clientId>`

Todas com header `Authorization: <VITE_MIGGO_API_KEY>` (`useClientPlatforms.ts:38,99-101`). Se nenhuma rede for reconhecida pelo nome do plano, cai de volta na regra antiga: redes com `PlatformIntegration.status === 'active'` (`useClientPlatforms.ts:112-119`).

**Uso real** (`src/pages/Content/CreatePostModal.tsx:58`):
```ts
const { activeNames, loading: platformsLoading } = useClientPlatforms(activeClientId ? Number(activeClientId) : null);
```
</Accordion>

<Accordion title="useOnboarding">
`src/hooks/useOnboarding.ts:56-122`

```ts
export const useOnboarding = (clientId: number | null | undefined): {
  status: OnboardingStatus | null;
  loading: boolean;
  error: string | null;
  refetch: () => Promise<void>;
  isComplete: boolean;
  currentStep: number;
  isInOnboardingFlow: boolean;
};
```

Consome `GET /api/v1/client/onboarding-status/<clientId>/`. Mantém um **cache em memória a nível de módulo** (`_cachedStatus`/`_cachedClientId`) para evitar race condition entre `OnboardingGuard` e `OnboardingFlow` ao navegar logo após completar o onboarding (`useOnboarding.ts:44-105`). `clearOnboardingCache()` é exportado à parte para invalidar esse cache.

`isInOnboardingFlow` é distinto de `!isComplete`: reflete se `onboarding_current_step` existe e não é `'done'` — use para decidir se a pessoa deve voltar à esteira (`useOnboarding.ts:114-121`).

**Uso real** (`src/components/OnboardingGuard.tsx:19-21`):
```ts
const { isComplete, status, loading: onboardingLoading } = useOnboarding(
  user?.role === 'client' ? clientId : null
);
```
</Accordion>

<Accordion title="useWelcomeTour">
`src/hooks/useWelcomeTour.ts:25-89`

```ts
export function useWelcomeTour(
  clientId: number | null | undefined,
  enabled: boolean
): { shouldShow: boolean; complete: () => Promise<void>; hide: () => void };
```

Controla a exibição única do tour de boas-vindas (MIG-227). O estado "já visto" é persistido no backend, não no navegador — via `ClientMeta` (chave `WELCOME_TOUR_META_KEY`, importada de `src/components/onboarding/WelcomeTour.tsx`), para não reaparecer ao trocar de dispositivo. Endpoints:
- `GET /api/v1/client/client-meta/list/?client_id=<clientId>`
- `PATCH /api/v1/client/client-meta/update/<metaId>/` (se já existe registro) ou `POST /api/v1/client/client-meta/create/` (se não existe)

`hide()` só esconde na sessão atual (reaparece na próxima visita); `complete()` é o único caminho que grava permanentemente (pulou ou concluiu o tour) (`useWelcomeTour.ts:56-86`).

**Uso real** (`src/pages/Dashboard/DashboardClient.tsx:59`):
```ts
const { shouldShow, complete, hide } = useWelcomeTour(clientId, enabled);
```
