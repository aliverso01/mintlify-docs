## Convenção de nomes observada no projeto

- **Componentes e páginas**: `PascalCase.tsx`, um componente por arquivo (ex.: `ClientSearchSelect.tsx`, `BrandkitEditor.tsx`).
- **Hooks**: prefixo `use`, `camelCase.ts` — exceto `authHook.ts`, que foge do padrão (é o hook de autenticação, mas o arquivo não se chama `useAuth.ts`; o hook exportado de dentro dele é `useAuth`).
- **Contextos**: `NomeContext.tsx`, exportando o `Provider` e um hook de consumo (`useX`) no mesmo arquivo.
- **Services/utils**: `camelCase.ts`, funções nomeadas exportadas (sem classes).
- **Pastas de página por domínio**: cada pasta de `pages/` pode conter sub-componentes e hooks locais exclusivos daquela tela (ex.: `pages/Content/useContentBoard.ts`, `pages/Dashboard/useDashboard.ts`) — hooks compartilhados por múltiplas telas vivem em `src/hooks/`, hooks de uma tela só ficam junto da própria pasta.
- Algumas pastas de `components/` usam PascalCase (`Clients/`, `Subscription/`, `UserProfile/`) e outras lowercase (`auth/`, `common/`, `form/`) — inconsistência existente no código, não corrigida aqui (ver seção de inconsistências no relatório final).

## `dist/`

Saída do build de produção (`vite build`), gerada por `npm run build`. Não deve ser versionada nem editada manualmente; é o diretório copiado para a imagem Nginx (`dockerfile:18`).

## Arquivos de infraestrutura (raiz do repo)

| Arquivo | Papel |
|---|---|
| `dockerfile` | Build multi-stage: `node:20-alpine` compila (`npm install && npm run build`) e o resultado (`dist/`) é copiado para uma imagem `nginx:stable-alpine`. Recebe `VITE_MIGGO_API_KEY` e `VITE_API_BASE_URL` como build args (`dockerfile:1-21`). |
| `nginx.conf` | Config estática do Nginx (usada como referência/documentação) — serve a SPA (`try_files ... /index.html`) e faz proxy de `/api` para `https://api.miggomkt.com.br` fixo (`nginx.conf:15-40`). |
| `nginx.conf.template` | Mesma config, mas parametrizada com `${BACKEND_URL}`/`${BACKEND_HOST}`, processada em runtime pelo `docker-entrypoint.sh` (`nginx.conf.template:19-20,25,29`). |
| `docker-entrypoint.sh` | Extrai host/URL do backend de `VITE_API_BASE_URL`, roda `envsubst` sobre `nginx.conf.template` e inicia o Nginx (`docker-entrypoint.sh:1-14`). |
| `docker-compose.yml` | Sobe o serviço `miggo-frontend` atrás de Traefik, com roteamento por domínio (`plataforma.miggomkt.com.br`) e headers `X-Forwarded-Proto` (`docker-compose.yml:1-27`). |
