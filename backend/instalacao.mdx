O `backend-miggo` é a API principal da plataforma Miggo, escrita em Django. Esta página cobre a preparação de um ambiente local funcional.

<Note>
  O ambiente de trabalho oficial deste monorepo usa a venv em `backend-miggo/venv/Scripts/python.exe` (Windows), criada com **Python 3.14**. Já a imagem Docker de produção (`dockerfile:1`) usa `python:3.11-slim`. As duas convivem hoje no projeto — não há um único Python "oficial" documentado no código; use 3.11+ para evitar surpresas de compatibilidade com produção.
</Note>

## Pré-requisitos

- **Python** 3.11+ (venv local do projeto está em 3.14; a imagem Docker usa 3.11).
- **PostgreSQL** — `docker-compose.yml:6` sobe `postgres:16`. `DATABASES.default.ENGINE` em `core/settings.py:206` é `django.db.backends.postgresql` (via `psycopg2-binary`, `requirements.txt`).
- **pip** e capacidade de compilar/instalar `cryptography`, `pillow`, `psycopg2-binary` (dependências nativas).
- **Playwright + Chromium** — usado pela raspagem de sites como último recurso quando o site recusa GET simples (`dockerfile:11-13`). Rode `playwright install --with-deps chromium` depois de instalar as dependências Python.
- Acesso às credenciais reais (Stripe, Asaas, OpenAI, ManyChat, Google OAuth, AWS S3, Jira, Apify, HtmlToCssImage) — pergunte à equipe; nenhuma é gerada localmente.

<Warning>
  `requirements.txt` está salvo em **UTF-16 LE** (confirmado por inspeção binária), não UTF-8. A maioria dos `pip` modernos lida bem com isso, mas se `pip install -r requirements.txt` falhar com erro de parsing, converta o arquivo para UTF-8 antes (`iconv -f UTF-16LE -t UTF-8`) — não é um problema do seu ambiente.
</Warning>

<Steps>
  <Step title="Clonar o repositório">
    ```bash
    git clone <url-do-repo> backend-miggo
    cd backend-miggo
    ```
  </Step>

  <Step title="Criar e ativar a venv">
    ```bash
    python -m venv venv
    # Windows
    venv\Scripts\activate
    # Linux/macOS
    source venv/bin/activate
    ```
  </Step>

  <Step title="Instalar dependências">
    ```bash
    pip install -r requirements.txt
    playwright install --with-deps chromium
    ```
    Principais libs (`requirements.txt`): `Django==5.2.7`, `djangorestframework==3.16.0`, `djangorestframework_simplejwt==5.5.1`, `django-cors-headers==4.7.0`, `drf-spectacular==0.29.0`, `django-crontab==0.7.1`, `psycopg2-binary==2.9.11`, `stripe==14.2.0`, `boto3==1.38.35`, `django-storages[s3]==1.14.6`, `google-auth==2.35.0`, `gunicorn==25.1.0`, `whitenoise==6.11.0`, `openai==2.8.1`, `yt-dlp`, `ffmpeg-python`, `playwright==1.61.0`.

    <Note>
      O docstring de `core/settings.py:4` fala em Django 6.0, mas a versão instalada real via `requirements.txt` é `Django==5.2.7`. Trate o comentário do arquivo como desatualizado.
    </Note>
  </Step>

  <Step title="Subir o PostgreSQL">
    Use o Postgres do `docker-compose.yml` (`postgres:16`) ou uma instância local. Crie o banco e o usuário que serão referenciados nas variáveis `DB_*` do passo seguinte.

## Rodando com Docker

O `dockerfile` builda a imagem de produção (`python:3.11-slim`, instala Playwright/Chromium, roda `collectstatic` e sobe via `gunicorn core.wsgi:application`). O `docker-compose.yml` sobe:

- `miggo-db`: Postgres 16 (senha/usuário fixos no compose — troque para segredo real em qualquer ambiente compartilhado).
- `miggo-api`: build local do `dockerfile`, exposto atrás de Traefik com roteamento por `Host(`api.miggomkt.com.br`)` — voltado a produção, não a uso local direto.

Para desenvolvimento local, prefira o fluxo de venv acima; o compose está desenhado para o servidor de produção (labels do Traefik, domínio fixo).

## Rotinas agendadas (cron) em desenvolvimento

`django-crontab` não funciona no Windows. Em dev, rode `python run_cron.py` para simular os jobs em laço (com intervalos bem mais curtos que produção — cuidado ao avaliar efeitos de cobrança). Para testar um job isolado, prefira `python manage.py <comando>`.

## Problemas comuns

<AccordionGroup>
  <Accordion title="manage.py test não cria o banco de teste">
    O usuário do Postgres local pode não ter permissão de `CREATEDB`. Nesse caso, `manage.py test` falha ao criar o banco de teste. Valide as alterações com `python manage.py check` e, quando possível, um import isolado do módulo alterado — não fique bloqueado tentando destravar a permissão do Postgres.
  </Accordion>
  <Accordion title="DEBUG sem valor derruba o processo">
    `DEBUG = config('DEBUG', cast=bool)` (`core/settings.py:34`) não tem `default=`. Sem `DEBUG` no `.env`, o Django falha na inicialização — é a variável mais fácil de esquecer.
  </Accordion>
  <Accordion title="requirements.txt em UTF-16">
    O arquivo está salvo em UTF-16 LE com CRLF. Se seu editor ou `pip` reclamar de caracteres inválidos, reabra/salve o arquivo como UTF-8 antes de instalar.
  </Accordion>
  <Accordion title="Login com Google falhando com 'Token used too early'">
    Ajuste via `GOOGLE_AUTH_CLOCK_SKEW` (`core/settings.py:364`) — o padrão do `google-auth` é zero de tolerância a diferença de relógio.
  </Accordion>
  <Accordion title="Playwright sem Chromium instalado">
    A raspagem de sites do onboarding cai para Playwright só quando o GET simples recebe 403 do site do cliente. Sem `playwright install --with-deps chromium`, esse fallback falha com "navegador de leitura não está disponível".
  </Accordion>
</AccordionGroup>
